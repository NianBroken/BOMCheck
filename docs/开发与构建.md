# 开发与构建

## 环境和依赖

以 Windows 11 x64 和 PowerShell 为基准。Node.js 必须系统级安装，版本至少 `22.18.0`，并提供 `npm.cmd`。构建入口直接执行 TypeScript 文件并使用 JSON 模块导入，因此不要用低版本 Node.js 绕过软件包声明。

在项目根目录运行：

```powershell
.\build\bootstrap.ps1
```

脚本使用系统公共应用数据目录下的 `BOMCheckToolchain` 作为默认设备工具链目录，将项目清单与锁文件复制到该位置并运行 `npm ci`。项目的 `node_modules` 是指向设备依赖的目录联接，不在项目内重新安装一份依赖。

可通过 `-ToolchainDirectory` 指定设备公共位置，目录必须位于源码目录之外。已有依赖路径与期望联接不符时，脚本会明确报错，应先核实该目录用途，再处理冲突，不强制覆盖。

依赖清单与 `package-lock.json` 是安装依据。构建读取 SheetJS、Tabulator 与 OverlayScrollbars 的已安装资源，不需要在运行插件的电脑另装这些依赖。

## 信息维护与生成文件

身份信息统一维护在 `extension-info.json`。仓库配置使用 `type` 与 `url`，当前为 GitHub 仓库 `https://github.com/NianBroken/BOMCheck`。扩展清单使用 `github` 类型，软件包清单使用 `git` 类型，二者指向同一地址。构建前统一检查六项文本身份字段及仓库对象，禁止缺失、空值、非法名称、空UUID或错误版本。中文名称、英文名称分别保存，描述为独立中文功能句。版本维持 `1.0.0`，不改变 UUID。

```powershell
node build/metadata.mjs
node build/metadata.mjs --check
```

生成模式同步扩展清单、软件包身份与锁文件根信息，并更新 README 身份区域。检查模式只核对，不写文件。不要删除 README 中的 `EXTENSION_IDENTITY_START` 与 `EXTENSION_IDENTITY_END` 标记。

`ui/pages.json` 管理七个页面标题和说明，`ui/commands.json` 管理按钮及菜单文案，`src/messages.ts` 管理业务提示，避免在不同流程分别定义同一文案。

`dist/index.js`、`iframe/index.html`、`build/dist`、`dependency-versions.json` 是构建输出。最终修改必须落在对应源码或集中配置中，不能只编辑输出文件。

## 检查和独立测试

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
```

类型检查与静态检查先核对集中元数据。静态检查以零警告为标准。默认测试执行 `tests/unit.ts`，其中包含合并填充单元测试，并核验插件身份、日志结构和 Excel 源码基准。临时构建与测试结果写入 `tests/output`，不写入文档目录。

独立测试覆盖文件解析、分隔符、位号比较、来源冲突、属性合并、空值、覆盖确认、错误隔离、批量删除及 Excel 输出。它使用隔离数据与宿主替身，不证明某个真实客户端已成功导入。

## 外部参考文件基准

真实参考基准与独立测试分开执行：

```powershell
node tests/run.mjs "参考数据目录的实际路径"
```

目录必须包含原基准对应的三份 `.xlsx` 文件，以及顶层 `.epro2` 工程归档。测试递归查找工作簿，从工程归档中的 `.epru` 读取参考 PCB 位号，检查预定的 782 个器件、479 个匹配位号与 303 个工程独有器件等结果。

这不是任意工程通用测试入口。缺少文件或内容不符合原基准时必须报告失败，不能换成其他文件却保留原有期望值。运行前检查输入，未提供参数时只执行独立测试，不猜测桌面目录。

其他宿主与界面测试保留在 `tests`，包含 CLI、调试通道和历史专项场景。部分脚本要求对应客户端、会话、测试工程或前序测试输出。使用前阅读参数与输入要求，不把这些脚本批量执行当作无前提的默认检查。

## 构建与交付

```powershell
npm.cmd run build
node build/deliver.mjs
node build/verify-delivery.mjs
```

构建先同步元数据，再由 esbuild 分别打包宿主入口和窗口页面脚本，将页面脚本、表格样式、滚动条样式及项目样式内联到生成页面。随后按 `build/package-files.mjs` 的共享清单生成 `.eext` 与 SHA-256，并记录实际安装的依赖版本。

实际打包由共享白名单决定，不通过 `.edaignore` 递归收集整个源码目录。修改排除文件不会扩大安装包内容。安装包只包含运行清单、脚本、页面、图标、README、CHANGELOG 与插件自身 LICENSE。

交付脚本先核验当前包，再替换项目内的旧交付目录，收录安装包、对应校验文件和必要文档，并生成 `SHA256SUMS.txt`。不生成源码归档、验收报告或历史测试证据副本。

核验检查归档 CRC、文件集合、元数据、内联资源、包内文档、许可证原文、入口及交付哈希。它不读取历史截图或客户端结果，不声称已经在真实宿主完成测试。

## 真实宿主验证

使用隔离工程导入本次 `.eext`，确认菜单与七个页面正常打开。导入包含已知匹配位号和两类差异的清单，核查预览、差异、属性预演、Excel 导出及 JSON 日志。

填写与删除必须使用测试工程，验证确认取消、实际修改、结果读取及保存。记录真实客户端版本。不要用曾经生成的截图、输出或旧包测试结果代替当前包验证；没有执行真实导入时只能报告归档核验结果。
