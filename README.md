# 物料核对

物料核对是一款运行在嘉立创EDA专业版中的扩展，英文名称为 BOMCheck。

按器件位号核对物料清单与原理图或印制电路板，支持清单预览、双向差异检查、属性合并填充、器件删除确认及结果导出。

## 项目用途与功能边界

物料清单中的位号用于指出一个物料对应哪些工程器件。例如，清单一行列出 `R1,R2,R3`，表示三个电阻使用同一行物料信息。工程修改后，清单仍保留已经删除的位号，或者工程出现清单未收录的新位号，就会形成两类差异。本插件把清单位号拆成独立记录，与选定原理图或印制电路板中的器件逐项核对，分别展示两类结果。

另一类工作是把清单中的制造商、供应商编号或描述填回工程。插件允许为一个目标属性选择一个或多个来源列，按指定顺序合并，并在执行前显示原值和目标值。例如，把“阻值”和“精度”列合并为描述，或者把“采购编号”列填写到供应商编号。

插件检查的是位号是否同时存在，不会自动检查所有属性是否相等，不验证电气连接、封装兼容性、采购库存或物料价格。清单独有器件仅供查看和导出，不会自动放置器件。插件不修改位号、封装、符号、网络及三维模型等结构信息，不提供自动回滚或一键恢复。

安装包适用于嘉立创EDA专业版扩展管理器，不适用于标准版，也不是浏览器扩展。使用插件不需要安装 Node.js、Python 或开发依赖；这些工具只用于源码开发和构建。

## 安装与启动

1. 准备 `bomcheck_v1.0.0.eext`。保留原文件格式，不解压后导入，不把源码压缩包当作安装包。
2. 打开嘉立创EDA专业版。V3 的官方入口为顶部“高级”菜单中的“扩展管理器”，再选择导入。V2 的官方入口为“设置 → 扩展 → 扩展管理器 → 导入扩展”。本项目清单要求 `>=3.2.0`，V2 入口仅用于解释平台菜单差异，不代表本插件支持 V2。
3. 选择安装包，在已安装列表中确认“物料核对”已启用。顶部菜单显示方式由扩展管理器设置控制；未设置为顶部显示时，从“高级”菜单查找扩展入口。
4. 打开包含原理图或 PCB 的工程，进入“物料核对 → 启动核对”。菜单也注册在首页和空白环境中，但读取器件必须有当前工程。
5. 打开后默认显示“导入设置”。“插件信息”菜单显示中文名称、英文名称、版本、作者及网站。

安装入口以[官方扩展使用说明](https://prodocs.easyeda.com/en/api/user-guide/using-extension.html)为依据。清单中的 `>=3.2.0` 是版本声明，不是对每一个未来版本已经完成实测的保证。宿主不提供所需接口时，应记录具体版本与问题明细，不用清单范围代替实际兼容性验证。

## 一次完整核对

1. 在“导入设置”的“工程范围”中选择一个处理对象。选中原理图时处理其全部图页，选中 PCB 时处理该 PCB。不会同时处理所有原理图和所有 PCB。
2. 点击“导入清单”，选择本地 `.xlsx`、`.xls`、`.csv` 或 `.tsv` 文件。一次选择一份文件，选择同一文件可重新读取。
3. 核实工作表、表头行和位号列。表头行从 `1` 开始计数。自动选择只是帮助定位，实际内容必须由使用者确认。
4. 核实位号分隔符和“忽略位号大小写”选项，在“数据预览”查看拆分后的位号、原始行号与来源列。
5. 返回“导入设置”，点击“核对器件”。读取原理图时会依次打开各图页，并显示读取进度。
6. 查看“工程独有”“清单独有”和“问题明细”。结果摘要给出工程图元数、清单位号数、匹配位号数及两类差异数，这些计数的单位不完全相同。
7. 需要保存结果时，点击“保存差异”。需要修改属性时进入“属性填充”；需要删除余件时进入“工程独有”。修改前应另行保存工程副本。
8. 写入或删除结束后，查看“操作日志”并点击“保存日志”。工程差异会失效，再次核对后才能继续基于当前工程操作。

只读取和核对不会填写或删除器件，但遍历图页会改变宿主当前显示的文档，代码没有恢复到原图页的步骤。修改工程范围后点击“重载工程”可重新读取范围列表，既有差异和映射也会清除。

## 七个页面分别做什么

| 页面 | 实际用途 | 应观察的结果 |
| --- | --- | --- |
| 导入设置 | 选择工程范围、文件、工作表、表头行、位号列及拆分规则，启动核对和保存差异 | 文件名、范围名称及核对摘要与准备处理的对象一致 |
| 数据预览 | 展示有效清单记录，每个拆分位号单独一行 | 位号、来源行号和各列内容完整，未把总标题误作表头 |
| 工程独有 | 展示工程存在而清单不存在的器件，提供删除入口 | 每条记录包含文档身份、图元身份及读取到的器件属性 |
| 清单独有 | 展示清单存在而工程不存在的有效来源记录 | 能按来源行回到原清单核查，不自动创建器件 |
| 属性填充 | 创建目标属性与来源列的映射，预演并执行填写 | 每项变更都有原值、目标值及合并来源 |
| 问题明细 | 展示解析、匹配、清洗与执行问题 | 根据阶段、行号、位号、字段及详情定位原因 |
| 操作日志 | 展示当前窗口最近一次写入或删除结果并保存日志 | 能区分成功、跳过、取消、失败和保存失败 |

结果表格提供列筛选、排序、横向滚动及纵向滚动。双击一行可以查看完整信息。筛选只改变显示结果，导出和删除仍使用完整业务集合。无数据和筛选后无数据分别显示状态说明，不把提示文字当作器件记录。

## 文件、表头与文本编码

### 工作表与表头识别

插件读取工作簿中的实际单元格，不仅依据文件声明的行列范围。表头候选优先寻找单元格文本精确为“位号”的行，其他非空行按不同文本数量排序。工作表也优先选择包含该文本的表；没有精确匹配时选择第一张表。

当表头中恰好有一个名为“位号”的列时，自动选中该列。列名为 `Designator`、存在多个“位号”列或者表头不在自动候选行时，需要手动选择。列以位置区分，重名和空白表头不会互相覆盖，界面用列字母与列名帮助定位。

只处理所选表头之后的非空行。完全空白行跳过；存在其他数据但没有有效位号的行记入问题明细；表头列名为“位号”时，后续再次出现该表头文本会作为重复表头跳过。不要把清单页脚、说明行或数量汇总当成普通器件行。

### 编码选择

Excel 工作簿按工作簿格式读取，文本编码选项用于 CSV 和 TSV。自动模式识别 UTF-16 LE 与 UTF-16 BE 的字节标记，无这些标记时严格按 UTF-8 解码，不会自动猜测 GBK。

| 文件实际编码 | 应选择的设置 |
| --- | --- |
| UTF-8 | 自动识别或 UTF-8 |
| GBK、GB18030 | GB18030 / GBK |
| UTF-16 LE | 有标记时自动识别，否则明确选择 UTF-16 LE |
| UTF-16 BE | 有标记时自动识别，否则明确选择 UTF-16 BE |
| Big5 | Big5 |

选错编码后，应选择正确编码重新解析。不要继续使用乱码预览核对工程。TSV 明确以制表符分列，CSV 由工作簿读取库解析分隔形式。

### 合并单元格、公式和错误

读取工作簿时保留原始单元格，再展开合并区域左上角的值，因此纵向合并的属性可以随每一行位号参与处理。合并区域内已有其他不同内容时，相关行被标记为冲突，问题明细保留原因。单个合并区域超过一百万个单元格时拒绝处理。

错误单元格和没有缓存结果的公式会形成解析问题。插件读取文件内保存的结果，不提供公式重算。先在表格软件中重新计算并保存，再重新导入。ZIP 格式工作簿先进行归档校验和内存重组，再交给 SheetJS 读取，用于兼容流式写出的归档结构。

## 位号规则与差异含义

默认分隔符为英文逗号 `,`、中文逗号 `，` 和顿号 `、`。例如，`R1,R2、R3` 形成三个位号记录，每条保留同一来源行的属性。可添加或移除分隔符，分隔符按完整文本匹配，多字符分隔符也按字面解释，不按正则表达式执行。

拆分后去除每个位号两端空白，同一单元格内完全相同的拆分文本去重。默认忽略大小写，`r1` 与 `R1` 使用同一个匹配键；关闭该选项后两者分别匹配。空格不是默认分隔符，`R1 R2` 不会自动拆分；如需按空格拆分，应明确添加空格分隔符。

`R1-R5` 不会自动展开为五个位号。应在原清单中列出完整位号，不要添加连字符分隔符来模拟范围展开，否则只会得到端点文本。

- **工程独有**：工程有该位号，清单位号索引没有该位号。
- **清单独有**：清单有该位号，工程位号索引没有该位号，只展示有效来源。
- **匹配**：两个索引同时存在该位号，不表示属性相等，也不表示没有重复或冲突。

工程中没有位号的器件会进入问题明细。同位号对应多个工程图元时，只有共享非空唯一标识、每个单元名非空且互不重复的组才作为无歧义多单元器件处理。其他重复位号组会报告冲突，并排除对应写入或删除。

同一位号在清单多行出现时保留来源记录。填写某个来源列时，这些行的文本必须一致；不一致则跳过受影响字段并报告冲突。冲突合并区域的原始位号也会参与存在性索引，避免覆盖后的数据把本来存在的器件误判成工程余件。

## 属性填充

### 操作步骤

1. 完成核对后进入“属性填充”，点击“创建映射”。
2. 选择目标属性，再选择一个来源列。例如，目标选择供应商编号，来源选择清单的采购编号列。
3. 同一目标需要多列内容时点击“添加来源”，用“上移字段”“下移字段”排列顺序。一个组内不能重复选择同一列，不同组不能使用同一个目标属性。
4. 多来源组显示合并分隔符输入框。留空直接拼接，输入 `/` 则用斜杠连接。分隔符不能含空格、换行或其他不可见字符；单来源不使用分隔符。
5. 默认不勾选“使用BOM空值清空目标属性”。确认确实需要清空已有文本时再勾选，并检查预演结果。
6. 点击“预演写入”，检查每条记录的原值、目标值、合并来源和合并分隔，同时查看问题明细。
7. 点击“写入属性”，程序会重新生成预演与执行计划。有已有内容需要覆盖时，显示整批覆盖确认；全部填入空目标时没有该覆盖确认框。
8. 执行后查看操作日志。成功表示重新读取的属性与目标值一致。保存失败单独记录，不能把属性写入成功当成文档已经保存成功。

### 可填写的属性

标准目标包括名称、制造商、制造商编号、供应商、供应商编号和加入 BOM。原理图器件还包含转到 PCB。普通其他属性取自实际读取到的工程属性，并提供描述 `Description` 目标。界面不提供任意新增属性名称的输入框。

器件库关联、符号、封装、位号、唯一标识、三维模型、层与层次路径等结构属性不作为普通文本目标。读取和详情显示某项数据，并不代表允许填写该项数据。

“加入BOM”和“转到PCB”属于真假值，只接受 `true`、`1`、`是` 或 `false`、`0`、`否`，英文不区分大小写。其他文本作为无效输入报告，不能用任意非空字符串代替“是”。空文本不能通过真假值校验，勾选空值清空也不会把它自动变成“否”。

### 合并与覆盖规则

多来源按界面顺序连接，只使用含可见内容的来源，空来源不产生多余分隔符。假设阻值为 `10k`、精度为空、封装说明为 `0603`，分隔符为 `/`，结果为 `10k/0603`。单个来源中的文本保留原显示内容，不自动裁剪成另一种格式。

默认跳过合并后为空的目标。开启空值清空后，可用空文本清空文本目标。当前值与目标值的文本表示一致时不产生实际写入。同一位号的冲突来源或无效记录会阻止对应字段填写，不通过猜测选取其中一行。

执行前重新读取器件并核对位号和唯一标识。预演后目标字段被其他操作改变时，跳过该字段，避免覆盖新内容。一个器件的有效字段合并成一次宿主修改，修改后重新读取核验；局部失败记录后继续处理其余器件。整批操作不是全有或全无的事务，失败不会自动撤销已经成功的部分。

## 删除工程独有器件

进入“工程独有”核实完整差异，点击“删除余件”。确认框说明处理对象、文档数量和候选器件数量。放弃确认不会删除；确认后按文档分批处理，每批最多四十个器件。

删除目标来自完整差异集合，列筛选、排序、滚动位置都不会缩小范围。不要认为表格只显示一行就只删除这一行。存在位号歧义的组不进入有效删除候选，清单没有器件记录或没有有效候选时不执行，清单包含解析阶段问题时也拒绝删除。

执行前重新读取器件身份，批量删除后读取剩余图元标识核实结果，未删除成功的对象继续单独处理。日志逐项记录删除成功或删除失败，文档保存失败另行记录。

删除会实际移除原理图或 PCB 中的器件。修改前保存的恢复数据是属性与身份快照，不是能够完整重建图元的工程备份。应在操作前通过宿主保存工程副本，插件没有导入恢复记录并重建器件的功能。

## 导出文件与记录保留

### 差异工作簿

“保存差异”导出 `.xlsx`，固定包含“工程有_BOM无”和“BOM有_工程无”两个工作表。工程侧保留读取到的标准属性、普通其他属性、文档和图元身份及结构详情；清单侧保留来源列、来源行、原始单元格和同位号其他有效来源信息。

有差异时生成列标题和筛选区域；某一侧没有差异时，工作表仅保留明确的空状态，不生成伪造的器件行或业务筛选区域。数据按文本写入，保留 `00123` 一类编号，不把以等号开头的业务文本当成公式执行。

导出基于完整核对结果，不仅导出表格当前筛选可见行。文件名包含“物料核对_差异”和时间戳，由宿主文件保存接口处理。修改完成后差异失效，应重新核对再保存新的差异。

### 操作记录

“保存日志”导出 UTF-8 JSON，顶层结构如下：

```json
{
  "metadata": {
    "author": "NianBroken",
    "website": "https://www.klaio.top/",
    "version": "1.0.0"
  },
  "recovery": null,
  "operation": []
}
```

`metadata` 是插件基础信息。`operation` 为当前窗口最近一次执行记录，包含位号、文档、字段、结果和说明，填写记录还包括原值、目标值及合并来源。各结果类型保留其实际需要的字段，不强制每一行具有相同字段。

`recovery` 来自扩展用户配置中的 `recovery` 项。写入前保存范围、计划和创建时间，删除前保存范围、候选快照和创建时间。后一次操作覆盖同一个配置项，不形成无限历史。没有保存过恢复数据时导出 `null`，宿主返回配置文本时原样作为文本保留，不强制转换为对象。

恢复数据在执行确认之前保存，因此取消后也能看到该次计划或候选，不能把它当作已经执行的证据。恢复数据持久保存，当前操作列表只在窗口内存中保留；关闭后重开，列表为空，但仍可导出既有恢复数据。需要长期保存每一批结果时，应在每批完成后及时导出。

## 运行机制、架构与依赖

宿主读取 `extension.json` 并注册菜单。入口脚本导出 `openBomCheck` 与 `about`，前者调用 `sys_IFrame.openIFrame` 加载包内页面。页面直接使用官方注入的 `eda` 对象，没有自建服务器、HTTP 业务接口或远程物料查询服务。

页面把文件读取结果转换为统一清单数据，再把所选文档中的器件转换为快照。比较模块建立位号索引，生成差异与问题。属性映射生成填写计划，操作服务通过宿主适配层重新读取、修改或删除器件并保存文档。显示与导出使用共同的数据转换，避免两者字段解释不同。

| 代码部分 | 职责 |
| --- | --- |
| `src/index.ts`、`src/metadata.ts` | 菜单导出入口、窗口启动及插件身份信息 |
| `src/ui.ts` | 页面状态、事件顺序、结果失效与操作编排 |
| `src/bom.ts`、`src/compare.ts` | 文件解析、位号记录、差异索引和填写计划 |
| `src/host.ts`、`src/operations.ts` | 官方宿主接口适配、执行前校验、批量操作和保存 |
| `src/model.ts`、`src/rules.ts`、`src/messages.ts` | 数据结构、集中规则和中文提示 |
| `src/mapping-editor.ts`、`src/separators.ts` | 属性映射与位号分隔规则编辑 |
| `src/table.ts`、`src/tabs.ts`、`src/scrollbars.ts` | 表格、页面切换、滚动位置与资源释放 |
| `src/file-picker.ts`、`src/display.ts` | 标准文件选择、详情与导出记录转换 |
| `ui` | 页面骨架、样式、页面定义和统一按钮文案 |
| `build`、`tests` | 构建交付入口、单元及宿主测试代码 |

项目不使用 React、Vue 或后端框架。TypeScript 负责源码类型，浏览器标准控件负责基础交互；Tabulator `6.7.1` 展示和筛选数据；OverlayScrollbars `2.17.0` 管理滚动区域；SheetJS CE `0.20.3` 解析清单并导出 Excel；JSZip `3.10.1` 校验和重组工作簿归档，也用于扩展打包。

构建依赖 esbuild `0.28.2`、TypeScript `5.7.3`、ESLint `10.14.0`、Antfu 配置 `10.0.0`、嘉立创EDA接口类型 `0.4.27`、fs-extra `11.3.0` 及其类型 `11.0.4`。依赖实际版本以软件包清单和锁文件为准，构建时另生成依赖版本信息。SheetJS 使用软件包清单中的官方分发地址，不用 npm 上同名旧版本替代。

宿主和页面脚本分别打包，页面脚本及所需样式内联到 `iframe/index.html`。安装后不需要从外部地址下载这些脚本或样式。官方窗口资源加载存在递归解析限制，内联资源与本项目构建方式相对应。第三方库是打包代码的组成部分，不是用户还需要在扩展管理器另行安装的插件。

更多维护细节见源码目录中的 `docs/开发与构建.md` 与 `docs/架构与接口.md`。安装包 README 不依赖这些未随包收录的文件即可完成日常操作。

## 常见问题与实际限制

| 表现 | 检查与处理 |
| --- | --- |
| 启动后没有工程范围 | 打开包含原理图或 PCB 的工程，再点击重载工程；确认当前工程已经完成加载 |
| 导入后不能核对 | 核实工作表、表头行、位号列和至少一条有效位号记录 |
| 清单列错位或出现乱码 | 核对文件格式与文本编码，检查所选表头是否是真实列标题，重新导入 |
| R1 与 r1 没有按预期区分 | 检查忽略位号大小写选项，修改后重新核对 |
| R1-R5 无法匹配 | 把范围改为实际列出的完整位号，插件不展开范围 |
| 预览有记录但部分字段未填写 | 查看重复来源冲突、空值、真假值、结构属性排除及字段在预演后变化等问题 |
| 显示成功但又出现保存失败 | 属性修改与文档保存是不同步骤，核查宿主中的实际值并完成保存，不直接重复整批覆盖 |
| 导出日志中有计划却没有成功行 | 恢复数据先于确认保存，核查实际操作记录，不能据此认定已经修改 |
| 删除被拒绝 | 修正解析问题、无效或空清单，检查有效差异与位号歧义，重新核对 |
| 操作后差异列表消失 | 结果已失效，重新核对后才能导出新差异或继续修改 |

读取原理图以全部图页为范围，任一图页读取失败不返回该次不完整的器件集合。工程切换会触发身份核查，不允许把既有范围直接应用于另一个工程。运行时会按宿主是否提供文档就绪接口选择等待方式，旧接口环境通过连续稳定读取确认图元集合。

操作期间应保持目标工程不变，不同时从其他窗口编辑同一批器件。程序会核查身份和目标字段，但不会把整个工程锁定为事务。窗口关闭时释放文件控件、事件订阅、表格、滚动区域和观察器；关闭窗口不是对已完成修改的撤销操作。

## 源码检查与打包

开发构建以 Windows 11 x64 为基准，要求系统级 Node.js `>=22.18.0`。在项目目录使用 PowerShell：

```powershell
.uildootstrap.ps1
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npm.cmd run build
node build/deliver.mjs
node build/verify-delivery.mjs
```

环境脚本从系统公共应用数据目录确定设备工具链位置，通过锁文件安装依赖，并在项目建立目录联接。默认单元测试不读取桌面上的外部文件；真实参考清单基准通过显式目录参数单独运行，输入要求见开发文档。

构建输出 `build/dist/bomcheck_v1.0.0.eext` 和对应 `.sha256` 文件。交付脚本收集当前安装包与必要文档到 `delivery`，核验脚本读取实际归档并检查一致性。不要仅修改生成的 `dist` 或 `iframe` 内容，后续构建会覆盖它们。
